# Spotify Network Traffic Analysis Using Wireshark

## 1. Project Overview

This project demonstrates a practical network traffic investigation conducted using Wireshark and Windows command-line tools.

The investigation examines network communication generated by Spotify, correlates an observed network connection with the running application process, analyses TCP connection establishment, and inspects TLS encryption.

## 2. Investigation Objectives

- Identify the running Spotify application process.
- Examine active network connections using Windows commands.
- Analyse the TCP three-way handshake.
- Inspect TLS negotiation and the selected cipher suite.
- Examine encrypted network traffic and its limitations.

## 3. Tools and Technologies

| Tool | Purpose |
|---|---|
| Wireshark | Network packet capture and analysis |
| Windows Command Prompt | Process and network connection identification |
| Tasklist | Running process identification |
| Netstat | Active network connection analysis |
| TCP/IP | Network communication analysis |
| TLS | Encrypted communication analysis |

## 4. Investigation Methodology

1. Launched Spotify on a Windows laptop.
2. Identified running Spotify processes using `tasklist`.
3. Used `netstat -ano` to examine active network connections and associated process IDs.
4. Captured network traffic using Wireshark.
5. Examined TCP connection establishment.
6. Inspected TLS Client Hello and Server Hello messages.
7. Examined encrypted TLS traffic and packet direction.

## 5. Key Findings

- Identified a Spotify process and correlated it with an active network connection.
- Observed a successful TCP three-way handshake.
- Identified TLS 1.3 as the negotiated protocol.
- Observed the cipher suite `TLS_AES_256_GCM_SHA384`.
- Examined 105 TLS records classified by Wireshark as Application Data: 63 outgoing and 42 incoming.
- Confirmed that encrypted traffic contents could not be interpreted without appropriate TLS decryption secrets.

## 6. Investigation Limitations

- This was an educational practical exercise conducted on a personal Windows laptop.
- Process-to-network correlation was based on observations during the practical session.
- The remote server identity was not independently verified.
- Encrypted payload contents were not decrypted.
- Packet counts alone do not establish the exact amount or content of application-level data transferred.
